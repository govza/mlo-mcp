# Domain context: mlo-mcp

Ubiquitous language for this repo. Terms are defined here in one or two lines; the deep definitions live in the reference docs under [docs/](docs/README.md) — follow the links rather than re-deriving behavior. When writing issue titles, test names, or proposals, use these terms exactly.

## The app and its data

- **MLO** — MyLifeOrganized, the Windows desktop outliner this server drives via `mlo.exe`'s command line ([docs/mlo/mlo-cli.md](docs/mlo/mlo-cli.md)).
- **Profile / `.ml` data file** — MLO's single binary data file. Auto-detected, never configured; the server never rewrites it.
- **Session block** — the run of MLO's own log tagged with one `mlo.exe` pid. The only source detection reads: the profile it last records that run opening is the open profile. Nothing MLO saved for next time (`LastDBFile`, the `MRU` list) is consulted ([ADR-0006](docs/adr/0006-detect-the-open-profile-from-the-process-alone.md)).
- **Corroborate** — what the running app's other two signals do to the answer its log gives: a window title naming the same file, and that file being held open. An *unavailable* signal never refutes; a contradicting one refuses.
- **Profile verdict** — detection's answer: the accepted data file, or a refusal. Refusals split by what a live session must do: `no-open-profile` and `contradicted` are definite (exit), `undetectable` means we could not tell (stay up). Never a guess.
- **Task tree** — one deep outline; deep nesting is idiomatic. The task model (computed-score priority, contexts, dependencies, visibility) is in [docs/mlo/mlo-task-model.md](docs/mlo/mlo-task-model.md).
- **Context (MLO "Place")** — `@Office`-style GTD context attached to tasks. Hierarchical (a context *includes* narrower ones) and optionally open only during declared hours.
- **To-Do list** — the flattened, ranked action list derived from the task tree; only tasks with no uncompleted children appear ([docs/mlo/mlo-task-model.md](docs/mlo/mlo-task-model.md) §1).
- **Next action** — a task the To-Do list would offer: a leaf that no flag, ordering rule, dependency, start date, or closed context is holding back.
- **Available / deferred** — the two states of a To-Do-list task: actionable now, versus a real action that something defers (a dependency, a start date, a closed context).
- **Container** — a task the outline declares as a grouping: a **project** (`IsProject`) or a **folder** (MLO's Folder flag — a bucket that never appears in the To-Do list itself, even once everything under it is done).
- **Path id** — positional id like `"1.2.3"`; shifts whenever the tree changes, valid only for immediate follow-up calls. Never stored.
- **GUID / UID** — a task's stable identity, resolved by aligning a fresh export against the row store, with the binary `.ml` recovery as cross-check ([docs/tools.md](docs/tools.md) → Shared semantics).
- **dataFileUID** — a profile's sync identity; keys all cloud-side state.
- **Binding** — the persisted profile → `dataFileUID` pointer, attached only by guarded auto-initialization or an explicit rebind, never by "the last UID seen". It lives in `bindings.json`, so it survives every restart.
- **Unbound sighting** — a `dataFileUID` seen syncing through the endpoint with no binding; recorded because the authority decision is the only place that learns the identity MLO actually syncs.
- **Binding mismatch** — a bound profile syncing under a different identity: writes would queue into a partition the app never reads. Reported by `cloud_status`, and now transient — the next proxied sync recovers from it ([ADR-0007](docs/adr/0007-recover-from-sync-drift-automatically.md)). It was to have been a write-gate refusal ([ADR-0002](docs/adr/0002-report-binding-mismatch-never-repair-it.md), reversed); that gate was never built.
- **Identity drift** — the cause of a mismatch: the `.ml` at a bound path is re-created (restore, rebuild, reset sync profile), so it syncs under a fresh `dataFileUID` while the path-keyed binding survives, still naming the identity that no longer exists. Not to be confused with the bare *drift* of [docs/mcp-cloud.md](docs/mcp-cloud.md) — MLO syncing behind the endpoint's back with the proxy off, which is not an error.
- **Identity-drift recovery** — the repair, run by auto-initialization with a candidate in hand: discard the abandoned partition *and everything queued in it*, release the binding, adopt the identity MLO actually presents. Automatic, destructive, and silent about the dropped writes — all three deliberate. Ground-truthing still runs but only warns, so adopting the wrong copy of a profile is possible ([ADR-0007](docs/adr/0007-recover-from-sync-drift-automatically.md)).

## The sync data plane

- **mcp-cloud / the endpoint** — the server's loopback HTTP sync endpoint (`127.0.0.1:8181` installed, `:8282` from a source checkout) that MLO reaches through its proxy setting ([docs/mcp-cloud.md](docs/mcp-cloud.md)).
- **Resident endpoint** — the long-lived process that owns the loopback listener and outlives every MCP session, auto-spawned by the first session that finds the port free ([ADR-0003](docs/adr/0003-resident-endpoint.md)). Started by re-invoking the server's own entry point with `--serve-cloud`.
- **Attached session** — an MCP server process. Every one of them attaches to the resident endpoint and none ever listens, so which client you are in never decides what works.
- **Injection** — how a write reaches the profile: the resident splices pending queue rows into a forwarded `Get` response for the bound `dataFileUID` only, presenting `vendorVersion + 1`, so MLO applies them as if another device had written them. Everything else runs in the session against the shared state root; the resident executes no tools.
- **GetFileTS nudge** — answering MLO's ~90 s background poll with that same advanced stamp while the queue is non-empty, so a pure-MCP write on a quiet MLO has a session to ride; verbatim once the queue empties.
- **Superseded** — the user answered MLO's sync-conflict dialog local-wins, so their row overwrote the injected write for the same UID. Detected by comparing the Apply's row content, never by UID presence; no retry, because re-injecting would just re-raise the dialog.
- **Session held open** — a forwarded `Get` with no following `Apply` beyond ~30 s: the endpoint's only cross-process sign that a conflict dialog is waiting on the user, surfaced by `cloud_status` as stalled delivery.
- **Upstream mode** — the only real-profile architecture: `MLO ↔ mcp-cloud ↔ vendor Cloud`. The endpoint is a transparent proxy for MLO's own sessions; the vendor stays the sole cursor authority, and the endpoint initiates a vendor call only during initialization.
- **Vendor contact** — a profile's own cloud credentials, scraped from its proxied sync traffic and held strictly in the resident's memory: never persisted, never logged, never crossing a process seam. Used for exactly one thing, the guarded initialization pull.
- **Local mode** — a retired binding value: the endpoint as a replacement cloud, deleted with the delta log. A partition still bound that way is refused at the authority decision, not served. Switching a profile between sync authorities was always unrecoverable ([docs/mlo/cloud-sync.md](docs/mlo/cloud-sync.md)).
- **Delta / envelope** — the sync unit: a ZIP/`data.csv` carrying complete 82-column task rows ([docs/mlo/cloud-sync.md](docs/mlo/cloud-sync.md)).
- **Row store** — the per-`dataFileUID` capture of the latest full 82-column row seen for each UID, harvested from every payload passing through. What update/complete author from and what identity resolves against; a gap refuses the write with the `repull` remedy. It replaced the *mirror*, which projected version-ordered state; this one only remembers rows.
- **Partition** — the per-`dataFileUID` state directory under the private state root; lifecycle `uninitialized → bootstrap-required → ready`, layout private to the repository tier.
- **Auto-initialization** — the resident binding a profile by itself after a proxied sync, with the binding written last, so any partial failure leaves none behind. There is no bootstrap tool to call. Of its original three guards only one still blocks — a candidate UID must exist; an existing binding is now drift to recover from, several candidates are chosen between, and a refuted ground-truth only warns ([ADR-0007](docs/adr/0007-recover-from-sync-drift-automatically.md)).
- **Ground-truthing a candidate** — proving a cloud file belongs to the open profile through contents, not identity (the `dataFileUID` appears nowhere in the `.ml`): the task GUIDs in the file's own footers against the pulled history's UIDs. It refutes on one observation only — two non-empty identity sets with nothing in common.
- **QuickSync** — `mlo.exe -QuickSync`; a best-effort accelerator, never load-bearing, and it opens no session at all when MLO believes nothing changed. MLO throttles the (deprecated) switch by invocation frequency, so the session debounces its after-write nudge to one per window (`MLO_QUICKSYNC_DEBOUNCE_MS`, default 5 min); within-window writes ride the GetFileTS poll. What delivers a write is MLO's own ~90 s sync cadence, nudged by the endpoint ([ADR-0005](docs/adr/0005-target-architecture-spec.md) §2).
- **Accept receipt / `writeId`** — what a write tool answers with, at durable accept: the queue holds the rows, MLO has not applied them. Keyed by `writeId`, not uid, because two queued writes can share one uid.
- **Write status** — the five states an accept receipt passes through, read back through `write_status`: `accepted | delivered | verified | expired | superseded`. `verified` is the advisory export re-align on top of `delivered` — part of the contract, not yet produced; it is no longer a boolean on a write's own answer.
- **Read-your-own-writes overlay** — the pending queue composed onto a fresh export at read time, so a caller sees its own accepted writes immediately (`pending: true` + the `writeId`). Derived, never stored: when a write leaves the queue (or its TTL passes) the entry drops silently and reads revert to export truth — loudness lives in `write_status` / `cloud_status`.
- **Tombstone** — a deletion record in a delta; `delete_task` tombstones a task and its whole subtree.
- **Dead letter** — the raw text of a write the server refused, appended to a file in the state root so the words survive a failure that queued nothing. Never replayed automatically.

## Failures

- **Failure kind** — the tagged name a refusal travels under (`unknown-row`, `binding-conflict`, …). Every kind this build can produce is declared once in `mcp-server/src/error-contract.ts` with its tier, its `retryable`, and what ends it ([ADR-0005](docs/adr/0005-target-architecture-spec.md) §6).
- **Failures as values** — a refusal crosses every boundary as a `ServiceResult` (`{ isErrored, value | failure }`), never as a throw. Exceptions are reserved for genuine invariant violations, such as a repository wired without a write driver.
- **Blast radius** — how far one failure reaches. Exactly four tiers: **event** (journaled, blocks nothing), **op refusal** (this call refuses, the next is fresh), **write-gate refusal** (every write refuses the same way until a state changes; reads untouched), **startup verdict** (refuse to start, exit 1 — allowed before serving only). Post-startup, nothing stops the server.
- **Remedy** — the concrete thing that ends a refusal, declared by the producer and carried with the kind. Caller metadata: nothing in this server ever retries automatically.
- **Advisory** — an event-tier observation riding along with a result that still succeeded; never a refusal.
- **Non-interference invariant** — the load-bearing rule of the proxy: every exchange MLO initiates is forwarded enriched or verbatim, and the only failure MLO may observe is genuine vendor transport failure (502). No state or failure of capture, row store, injection queue, binding, partition, or any service may block, delay, or corrupt it; the forward path reads nothing that can refuse ([ADR-0005](docs/adr/0005-target-architecture-spec.md) §6).
- **Sabotage suite** — the executable form of that invariant: the resident's handler stack in-process against a canned vendor session, one case per subsystem broken (throwing, corrupt on disk, or hanging), each asserting the session completed with the vendor's payload intact (`test/unit/cloud-sabotage.test.ts`).
- **Degraded to `unknown`** — a problem+json `type` an older session does not recognize, rehydrated with its wire type, title and extension members intact. Degraded, never lost, and never thrown.
